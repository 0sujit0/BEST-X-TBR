# Org Admin flows — agreed 2026-10-12 (D-014), updated 2026-10-28 (FSD v0.3, D-019, D-020)

## Roles (optional step, any time) — role-first, pending client confirmation
1. Roles section: create a role from scratch or copy an existing one; name, description, permissions by module (None / View / Edit / Custom ticks)
2. Role with admin modules → re-enter password
3. Role saved for reuse; editing applies to all its users; a role in use cannot be retired

## Add a user
1. Users → Create user: details (name, email = login ID, phone, locations, job title, certifications, clinic fields)
2. Choose role (one per user); "+ Create new role" shortcut. Summary of the role shown; MFA tick for non-admin users
3. Admin access given → re-enter password
4. Within active-user limit? No → ask BEST to raise it
5. Account created (status Invited, counts as active user); welcome email with temporary password
6. Per-user permission changes: removed under role-first (pending client; FSD v0.2 BR-07 allowed them)

## Add a client
1. Add client (profile, location); choose assessment type (VB-MAPP, ABLLS-R, Vineland) at setup — pending client
2. Record signed consent — therapist or Org Admin (D-020)
3. Assign care team (therapist and supervisor)
4. Schedule sessions — Org Admin today (D-014); Scheduler or BCBA proposed in 22 Oct review — pending client

## Also covered
- Deactivating a user: password re-entry; no longer counts as active user; open sessions end
- Archiving a client hides them from active work
- Consent withdrawal recorded by therapist or Org Admin
